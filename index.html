Ledger guarantees

Deterministic truth underneath every agent.

Agents can interpret messy financial reality. The ledger makes the final record explicit, balanced and reproducible.

01

Double-entry by default

Every approved journal balances within each asset. Debits and credits cannot silently drift apart.

02

Atomic writes

All postings in one ledger transaction commit together, or none do. Partial books never become the source of truth.

03

Idempotent agent actions

Retries use the same action key, so a repeated tool call cannot create the same financial event twice.

04

Track fiat, stablecoins, fees and FX effects side by side while keeping a separate balance for every asset.

Questions, answered

Where the operating layer fits.

OpenFlamma is designed to sit between raw financial activity, the agents working on it and the accounting systems that consume the approved result.

01Does this replace our ERP or general ledger?+

No. OpenFlamma is the operational financial layer underneath. It maintains the transaction-level evidence, agent actions and reconciled state, then sends approved journals and roll-ups to the accounting system you already use.

02Can an agent write to the ledger without approval?+

Only if you permit it. An agent can be read-only, draft-only, limited by amount or counterparty, or required to obtain human approval before any write is committed.

03Can we self-host the infrastructure?+

Yes. Run the open-source ledger and permission layer in your own environment, or use iBnk Cloud for a managed deployment with connectors and agent products included.

04Does it support fiat and digital assets together?+

Yes. The multi-asset model keeps separate balances for currencies and digital assets while linking conversions, fees and FX effects to the same order and evidence trail.
